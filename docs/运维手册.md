# Fly 博客系统运维手册（Rocky Linux 9.8 / 10.x Minimal）

| 项目 | 内容 |
|:---|:---|
| 文档版本 | 1.1 |
| 适用系统 | Rocky Linux 9.8 / 10.x Minimal（x86_64，10.2 已核对，含 DNF5 命令兼容），兼容 RHEL 系 |
| 部署方式 | Docker Compose v2 全栈（PostgreSQL + Spring Boot + Next.js + Nginx） |

## 1. 系统架构

```
Internet
   │  80/443
   ▼
┌─ 服务器（Rocky 9.8 / 10.x）──────────────────────────┐
│  nginx 容器 :80/:443（唯一对外入口，80 全部 301 → 443）  │
│    ├─ /api/、/uploads/、/reader3/ → backend:8000        │
│    ├─ /api/music、/api/uapis、/admin  → frontend:3000 │
│    └─ /（站点全部页面）                 → frontend:3000 │
│                                                      │
│  backend 容器 :8000  Spring Boot 3 + JDK 21          │
│    ├─ REST API / JWT / OSS 上传                        │
│    ├─ 随 jar 分发的 Vue 后台静态资源（不对外暴露）      │
│    └─ 内置小说阅读服务 /reader3/（数据源 biquga.com）   │
│  frontend 容器 :3000  Next.js 16（/admin 管理后台）    │
│  db 容器 :5432         PostgreSQL 16（仅容器内网可达）  │
└──────────────────────────────────────────────────────┘
```

| 服务 | 构建方式 | 对外端口 | 持久化 |
|:---|:---|:---|:---|
| `nginx` | `nginx:alpine` + `deploy/nginx.conf` | **80/443**（宿主机） | 无（证书在 `deploy/certs/`） |
| `frontend` | `fly/Dockerfile`（两阶段） | `127.0.0.1:3000`（仅调试） | 无 |
| `backend` | `fly-backend/Dockerfile`（三阶段：Vue→Maven→JRE） | `127.0.0.1:8000`（仅调试） | `./fly-backend/uploads`（宿主机目录） |
| `db` | `postgres:16-alpine` | 无（仅容器网） | 命名卷 `pgdata` |

数据说明：

- **数据库数据**存储在 Docker 命名卷 `pgdata`，`docker compose down` 不会丢失（只有 `down -v` 才删除）。
- **上传文件**存储在宿主机 `./fly-backend/uploads/`。
- **音乐库**只读挂载：默认 `./data/music/120`、`./data/music/mp3`（可在 `.env` 覆盖），不影响站点运行。
- `init_db.sql` 仅在数据卷**首次创建**时执行（建表 + 种子数据）。

## 2. 环境要求

| 项目 | 最低配置 | 推荐配置 |
|:---|:---|:---|
| CPU | 2 核 | 2 核+ |
| 内存 | 2 GB | **4 GB**（镜像构建阶段 Next.js 需要约 4 GB 堆） |
| 磁盘 | 20 GB | 40 GB+（镜像与构建缓存约占用 3~5 GB） |
| 系统 | Rocky 9.8 / 10.x Minimal（10.2 适用） | 同左 |
| 网络 | 可访问互联网（Docker Hub、GitHub、npmmirror、aliyun Maven） | 国内服务器建议配置镜像加速（见 3.1） |
| 权限 | root 或 sudo 用户 | root |

> **内存不足处理**：2 GB 机器必须先加 swap，否则 `pnpm build` 构建前端时会 OOM。
> 无 swap 时执行：
> ```bash
> sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
> sudo mkswap /swapfile && sudo swapon /swapfile
> echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
> ```

## 3. 系统初始化（仅全新服务器需执行）

### 3.1 安装 Docker（含 Compose v2）

```bash
# 基础工具（Minimal 不全，tar/curl 后面步骤要用）
sudo dnf install -y dnf-plugins-core tar

# 启用 CRB（原 PowerTools）与 EPEL
sudo dnf config-manager --set-enabled crb
sudo dnf install -y epel-release

# 添加 Docker 官方源（按 $releasever 自动匹配 el9/el10）
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# 安装 Docker 引擎与 Compose 插件
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

#腾讯云服务器安装环境|非本地环境
# 1. 清理之前配置失败的源文件
sudo rm -f /etc/yum.repos.d/docker-ce.repo

# 2. 添加腾讯云内网 Docker 源（注意替换为腾讯云专属地址）
sudo dnf config-manager --add-repo https://mirrors.tencentyun.com/docker-ce/linux/centos/docker-ce.repo

# 3. 刷新缓存
sudo dnf makecache

# 4. 安装 Docker
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 开机自启并启动
sudo systemctl enable --now docker

# 验证
docker --version && docker compose version
```

### 3.2 配置镜像加速（国内服务器 Docker Hub 拉取失败时）

```bash
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1panel.live",
    "https://docker.m.daocloud.io"
  ]
}
EOF
sudo systemctl restart docker
docker info | grep -A3 "Registry Mirrors"
```

> 镜像加速站可用性经常变化，若全部失效可搜索当前可用的国内加速地址替换。
> 国际带宽充足的服务器可跳过本节。

### 3.3 防火墙放行 HTTP/HTTPS

```bash
sudo firewall-cmd --permanent --add-service=http --add-service=https
sudo firewall-cmd --reload
sudo firewall-cmd --list-services        # 应包含 http https ssh
```

> 8000/3000/5432 不需要对公网开放（compose 已将 8000/3000 绑定到 127.0.0.1，
> 5432 仅容器内网可达）。云主机安全组同样只需放行 22/80/443。

### 3.4 SELinux

**保持默认 `enforcing` 即可**：项目 `docker-compose.yml` 中所有宿主机目录挂载均已
标注 `:z`（SELinux 重新标记），已在 SELinux 环境验证。无需关闭 SELinux。

```bash
getenforce        # 预期 Enforcing
```

## 4. 项目交付与部署

### 4.1 传输项目包

直接使用现成交付包 `fly-deploy-1.0.1-final.tar.gz`（`./` 结构，约 26.6MB，已排除
node_modules/.next/target/.git/.env 与数据目录）：

```bash
# 开发机上传
scp fly-deploy-1.0.1-final.tar.gz root@服务器IP:/opt/

# 服务器解压（注意：不要带 --strip-components）
sudo mkdir -p /opt/fly
sudo tar -xzf /opt/fly-deploy-1.0.1-final.tar.gz -C /opt/fly
cd /opt/fly
```

从源码自行打包（可选）——排除项与交付包保持一致，产出同样是 `./` 结构：

```bash
cd /path/to/fly
tar --exclude='./.env' \
    --exclude='node_modules' \
    --exclude='.next' \
    --exclude='target' \
    --exclude='.git' \
    --exclude='阿芙洛狄忒模型文件' \
    --exclude='admin/dist' \
    --exclude='tsconfig.tsbuildinfo' \
    --exclude='./db' \
    -czf fly-deploy-1.0.1-final.tar.gz .
```

解压命令与上面相同（不带 --strip-components）。其中 `./db` 是本地数据目录（干净项目不随包交付），
`阿芙洛狄忒模型文件/` 与 `admin/dist` 为源素材/过期构建产物，服务器用不到。

> 使用 git 克隆同样可行，注意 `.env` 不入库，需单独配置。

**项目必备文件清单**（缺失会导致构建失败）：

| 文件 | 用途 |
|:---|:---|
| `docker-compose.yml` | 全栈编排 |
| `.env`（由 `.env.example` 复制） | 密钥与可选配置 |
| `deploy/nginx.conf` | 反向代理规则 |
| `fly/`（含 `Dockerfile`、`pnpm-lock.yaml`） | 前端源码 |
| `fly-backend/`（含 `Dockerfile`、`pom.xml`、`init_db.sql`、`init_admin.sh`、`admin/`、`src/`） | 后端源码 + 初始化数据（`init_admin.sh` 挂载为 `zz-init-admin.sh`，负责创建 `feifei` 管理员账号，缺失则无账号可登录） |
| `docs/` | 本文档 |

### 4.2 配置 `.env`

```bash
cp .env.example .env

# 生成 JWT 密钥（必填，低于 32 字符后端拒绝启动）
echo "FLY_SECRET_KEY=$(openssl rand -hex 32)" >> .env

# 修改数据库密码（强烈建议）
vi .env    # POSTGRES_PASSWORD=改成强密码
```

可选项按需配置（详见附录 A）：阿里云 OSS（图片上传）、
音乐目录（`MUSIC_DIR_120/MP3`，不配置则用默认 `./data/music/*`）。
（GitHub OAuth 评论登录已移除，无需也无法配置。）

### 4.3 构建并启动

```bash
cd /opt/fly
docker compose up -d --build
```

首次构建约 10~30 分钟（下载基础镜像 + pnpm/maven 依赖 + Next.js 构建）。

**构建期已知无害告警**：`RSS generation failed: EAI_AGAIN backend` —— 构建环境
无法解析容器服务名 `backend` 所致，运行时 `/feed` 正常，可忽略。

### 4.4 启动状态检查

```bash
docker compose ps
```

预期四个容器全部 `running`，`db` 为 `healthy`：

```
NAME        STATUS                    PORTS
fly-db-1       running (healthy)   5432/tcp
fly-backend-1  running             127.0.0.1:8000->8000/tcp
fly-frontend-1 running             127.0.0.1:3000->3000/tcp
fly-nginx-1    running             0.0.0.0:80->80/tcp, 0.0.0.0:443->443/tcp
```

## 5. 部署验收（必须逐项通过）

```bash
# 本机 curl 统一用 https + -k（-k：localhost 与证书域名 feifei520.cn 不符，仅跳过校验）

# ⓪ HTTP 80 跳转
curl -s -o /dev/null -w "%{http_code}\n" http://localhost/
# 预期 301（Location 指向 https://$host$request_uri）

# ① 健康检查
curl -sk https://localhost/api/health
# 预期 {"status":"ok"}

# ② 首页
curl -sk -o /dev/null -w "%{http_code}\n" https://localhost/
# 预期 200

# ③ 管理后台页面（Next.js /admin）
curl -sk -o /dev/null -w "%{http_code}\n" https://localhost/admin
# 预期 200（返回 Next.js 登录页 HTML；带斜杠的 /admin/ 会 308 跳转到 /admin，属正常）

# ④ 管理员登录（密码为 .env 的 ADMIN_INITIAL_PASSWORD，脚本无默认值）
curl -sk -X POST https://localhost/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"feifei","password":"你的管理员密码"}'
# 预期 {"code":0,...,"data":{"accessToken":"..."}}（code=0 且 accessToken 非空）

# ⑤ 小说阅读服务（需服务器可访问 biquga.com）
curl -sk -N -G "https://localhost/reader3/searchBookMultiSSE" --data-urlencode "key=诡秘之主" \
  --max-time 20 | head -c 300
# 预期 SSE 流式返回包含搜索结果（data:{"lastIndex":...,"data":[...]}）

# ⑥ 封面图片代理（验证容器出站 HTTPS）
curl -sk -o /dev/null -w "%{http_code}\n" \
  "https://localhost/reader3/cover?path=https://www.biquga.com/img/2369.jpg"
# 预期 200

# ⑦ 证书有效期（应显示约 90 天后到期）
echo | openssl s_client -connect 127.0.0.1:443 2>/dev/null | openssl x509 -noout -dates
```

浏览器人工验收：访问 `https://feifei520.cn/`（地址栏锁标志），确认首页文章/说说/相册
正常渲染；`https://feifei520.cn/admin` 能用 feifei 登录；`/novel` 搜索一本书能打开
目录与正文。

**管理员账号**：用户名 `feifei`；密码为初始化时 `ADMIN_INITIAL_PASSWORD` 的值（脚本不设
默认密码，未设置会直接报错；`[init-admin]` 日志不打印密码）。

## 6. 日常运维

### 6.1 常用命令

```bash
cd /opt/fly

docker compose ps                      # 服务状态
docker compose logs -f backend         # 跟踪后端日志（frontend/nginx/db 同理）
docker compose logs --since 1h nginx   # 最近 1 小时 nginx 日志
docker compose restart backend         # 重启单个服务
docker compose up -d --build           # 代码更新后重建并滚动重启
docker compose down                    # 停止（数据卷保留，可再 up）
docker system df                       # 查看镜像/卷磁盘占用
```

### 6.2 服务自启

所有容器均为 `restart: unless-stopped`，Docker 引擎已设 `systemctl enable docker`，
服务器重启后全栈自动拉起。重启后用 `docker compose ps` 确认四个容器 `running`。

### 6.3 资源与健康监控

```bash
docker stats --no-stream                # CPU/内存快照
df -h / /var/lib/docker                 # 磁盘空间
du -sh /var/lib/docker                  # Docker 占用
curl -s http://localhost/api/health     # 应用健康
```

建议：配置云监控或 cron 巡检脚本监控磁盘 > 85% 告警、容器退出告警。

### 6.4 端口与访问入口

| 入口 | 地址 | 说明 |
|:---|:---|:---|
| 博客前台 | `https://feifei520.cn/` | Nginx 443（80 自动 301 跳转） |
| 管理后台 | `https://feifei520.cn/admin` | Nginx → frontend |

### 6.5 HTTPS 证书自动续签（acme.sh + Let's Encrypt）

> **当前状态（2026-09-30 已完成上线）**：证书已签发并安装，cron 自动续签生效，
> 下次续约窗口约 **2026-11-26**（90 天有效期，提前 30 天续）。证书数据在服务器
> `~/.acme.sh/`，迁移时整体备份该目录 + `deploy/certs/` 无需重配。

腾讯云免费证书**不支持自动续签**（90 天需手动重申请），生产方案用 acme.sh 走 ACME
自动续签，DNS-01 验证（自动加/删 TXT 记录，不依赖 nginx 与 80 端口状态）。

**一次性配置（约 10 分钟，root 执行）：**

```bash
# 1) 安装 acme.sh（会自动写入 cron）
curl https://get.acme.sh | sh -s email=2799852495@qq.com
source ~/.bashrc
acme.sh --set-default-ca --server letsencrypt

# 2) DNS 服务商 API 密钥——解析托管在哪就用哪家的插件，写错 zone 会 NXDOMAIN
#    本项目域名注册于阿里云，解析托管在阿里云云解析（NS dns29/30.hichina.com），
#    用 dns_ali：阿里云控制台 → RAM 访问控制 → 创建用户（勾「OpenAPI 调用访问」）
#    → 授权 AliyunDNSFullAccess → 拿 AccessKey ID/Secret（Secret 只显示一次，存密码管理器）：
export Ali_Key="LTAIxxxxxxxx"
export Ali_Secret="xxxxxxxx"

#    备用：若解析迁到腾讯云 DNSPod，用 CAM 子账号（QcloudDNSPodFullAccess）的
#    Tencent_SecretId/Tencent_SecretKey，签发命令换 --dns dns_tencent。
#    ⚠️ DNSPod 里有同名 zone ≠ 生效，以 dig NS 查到的权威 NS 为准
#    （曾误往腾讯 DNSPod 死 zone 写 TXT，Let's Encrypt 验证 NXDOMAIN）。
#    （真实密钥不要写进本文档，acme.sh 已保存在服务器 ~/.acme.sh/account.conf）

# 3) 签发 ECC 证书
acme.sh --issue --dns dns_ali -d feifei520.cn --keylength ec-256

# 4) 安装到项目目录 + 续签后自动热加载（acme.sh 记住该命令，每次续签自动执行）
chmod +x /opt/fly/deploy/reload-nginx.sh
acme.sh --install-cert -d feifei520.cn --ecc \
  --fullchain-file /opt/fly/deploy/certs/fullchain.pem \
  --key-file /opt/fly/deploy/certs/privkey.pem \
  --reloadcmd "/opt/fly/deploy/reload-nginx.sh"
```

> 首次启用且 nginx 容器尚未用新 compose 重建时，第 4 步的 reload 会报错，可忽略——
> 证书文件已就位，接着 `docker compose up -d nginx` 即可。已有腾讯云证书在线上的，
> install-cert 直接覆盖同名文件并热加载，无需停机。

**续签**：acme.sh 安装时已自动写入 cron（`crontab -l | grep acme` 可见），每 60 天
自动续签（Let's Encrypt 证书 90 天有效），成功后执行 reloadcmd，全程无感、无停机。

**手动续签 / 排障：**

```bash
acme.sh --list                              # 证书列表与下次续签时间
acme.sh --info -d feifei520.cn              # 配置详情（CA、reloadcmd 等）
acme.sh --renew -d feifei520.cn --ecc --force   # 立即强制续签一次
acme.sh --issue --dns dns_ali -d feifei520.cn --keylength ec-256 --debug 2  # 签发排障
```

注意：

- API 密钥只 export 一次即可，acme.sh 保存到 `~/.acme.sh/account.conf`；
  迁移服务器时整体备份 `~/.acme.sh/` 即可带走续签配置。
- CAM 密钥泄露等于可改你的 DNS 解析，务必用最小权限子账号，不要提交进任何仓库。

## 7. 备份与恢复

### 7.1 备份内容

| 数据 | 位置 | 重要性 |
|:---|:---|:---:|
| 数据库全量 | 卷 `pgdata` | ★★★ |
| 上传文件 | `./fly-backend/uploads/` | ★★★ |
| 站点配置 | `./.env` | ★★★ |
| 静态站点配置 | `siteConfig.ts`、`content/posts/`（在镜像内，改动需重建） | ★★ |

### 7.2 备份脚本

```bash
mkdir -p /opt/backup/$(date +%F)

# 数据库
docker compose exec -T db pg_dump -U postgres fly \
  | gzip > /opt/backup/$(date +%F)/fly.sql.gz

# 上传文件与配置
tar -czf /opt/backup/$(date +%F)/uploads.tar.gz fly-backend/uploads
cp .env /opt/backup/$(date +%F)/env.bak
```

建议用 cron 每日执行（保留最近 7 份）：将上述备份命令保存为
`/opt/fly/backup.sh`（首行加 `#!/bin/bash` 与 `cd /opt/fly`），然后：

```bash
chmod +x /opt/fly/backup.sh
crontab -e
# 每天 03:30 备份
30 3 * * * /opt/fly/backup.sh >> /var/log/fly-backup.log 2>&1
```

### 7.3 恢复

```bash
# 数据库恢复（危险操作，先 down 掉 backend 避免写入）
docker compose exec -T db psql -U postgres -d fly -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
gunzip -c /opt/backup/2026-09-27/fly.sql.gz \
  | docker compose exec -T db psql -U postgres -d fly

# 上传文件恢复
tar -xzf /opt/backup/2026-09-27/uploads.tar.gz -C /opt/fly

docker compose restart backend
```

> **数据库迁移/全量恢复**：更稳妥的做法是 `docker compose down` 后替换整个
> `pgdata` 卷数据，再 `up`。

## 8. 升级与回滚

### 8.1 升级（拿到新版本代码后）

```bash
# 1) 先备份（必须）
#    见 7.2，至少备份数据库和 uploads

# 2) 替换项目代码（保留 .env 与 uploads）
cd /opt/fly
mv .env /root/.env.keep && mv fly-backend/uploads /root/uploads.keep
# 解压新版本到当前目录（覆盖源码）……
mv /root/.env.keep .env && mv /root/uploads.keep fly-backend/uploads

# 3) 重建并启动
docker compose up -d --build

# 4) 验收（执行第 5 节全部检查项）
```

> 数据库结构变更不会自动执行（`init_db.sql` 只跑一次），新版本若含 DDL 变更，
> 需按版本说明手动 `docker compose exec -T db psql -U postgres fly` 导入增量 SQL。

**本版本增量说明**（关闭全部注册 + 监控方案 A）：

- 全站注册/登录功能已关闭：小说模块的 `/api/novel/register`、`/api/novel/login`、
  `/api/novel/admin/users*` 接口已移除，`novel_user`、`novel_user_progress` 两张表
  **不再由代码创建/读写**（老库可直接 `DROP TABLE novel_user, novel_user_progress;`）。
  阅读进度标签统一存 `novel_progress`（新增 `page_index`、`finished` 两列，后端启动时自动补齐），
  匿名可用。`app_error_log`（异常日志）由后端启动时自动创建，升级无需手动 DDL。
- 唯一保留的账号为管理员 `feifei`；**忘记密码时在数据库重置**（见第 9 节"重置管理员密码"）：
  `UPDATE public.user SET hashed_password = crypt('新密码', gen_salt('bf', 10)) WHERE is_admin = true;`
- 说说列扩容需**手动执行一次**（老库的 `chatter.content/images/mood` 为 varchar(255)/varchar(20)，
  超长图片 JSON 会写入失败）：

```sql
ALTER TABLE chatter ALTER COLUMN content TYPE TEXT;
ALTER TABLE chatter ALTER COLUMN images TYPE TEXT;
ALTER TABLE chatter ALTER COLUMN mood TYPE TEXT;
```

- 需管理员令牌的接口：`/api/admin/errors*`；
  评论/说说评论/留言一律匿名提交且默认 `pending`，由后台审核后展示。

### 8.2 回滚

```bash
# 代码回滚：恢复旧版项目目录后重新构建
docker compose up -d --build

# 数据回滚：用升级前的备份恢复数据库（见 7.3）
```

> 因此**任何升级前的备份都是回滚的前提**。建议升级前先
> `cp -a /opt/fly /opt/fly.bak-$(date +%F)`。

## 9. 故障处理

| 现象 | 排查 | 处理 |
|:---|:---|:---|
| `docker compose up` 报 `FLY_SECRET_KEY` 未设置 | `.env` 缺失或未填 | `cp .env.example .env` 并设置 ≥32 字符密钥 |
| 拉取镜像超时/失败 | Docker Hub 网络不通 | 配置 3.2 镜像加速；`docker pull postgres:16-alpine` 单独验证 |
| 构建前端报 `JavaScript heap out of memory` | 内存不足 | 加 2.0 节 swap 后重试 |
| 构建日志出现 `RSS generation failed: EAI_AGAIN backend` | 构建期 DNS，无碍 | **已知无害**，运行时 `/feed` 正常，忽略 |
| `db` 容器反复重启 | 密码与旧卷不一致 | 改回原 `POSTGRES_PASSWORD`，或备份后 `docker compose down -v` 重建（**会清空数据**） |
| 首页 502 | frontend 未起来 | `docker compose logs frontend`；确认 `docker compose ps` 全 running |
| 图片上传失败 | 未配置 OSS 或出站网络不通 | 配置 `.env` 的 `FLY_OSS_*`；`docker compose exec backend wget -qO- --timeout=10 https://gitee.com > /dev/null; echo $?` 测出站（0 为通） |
| 封面/小说搜索失败 | 服务器访问 biquga.com 不通 | `docker compose exec backend wget -qO- --timeout=10 https://www.biquga.com/ > /dev/null; echo $?` 测连通（0 为通）；镜像不带任何附加根证书，若所在网络有 TLS 拦截需自行在构建阶段导入其根证书 |
| 端口 80 被占用 | 宿主机已有 Web 服务 | `ss -lntp \| grep :80`，停用冲突服务或改 compose 端口映射 |
| SELinux 相关拒绝（avc denied） | 挂载未带 `:z` | 确认 compose 挂载均带 `:z`，`ausearch -m avc -ts recent` 查看 |
| 容器时间不准导致定时/证书异常 | 未同步时间 | `timedatectl set-ntp true`；`date` 校验 |
| 磁盘占满 | 镜像/日志堆积 | `docker system df`；`docker image prune -f` 清悬空镜像；清理旧日志 |
| 忘记管理员密码 | — | 见下方"重置管理员密码" |

**重置管理员密码**（在项目目录执行，将 `新密码` 替换为要设置的密码）：

```bash
docker compose exec -T db psql -U postgres -d fly \
  -c "UPDATE public.user SET hashed_password = crypt('新密码', gen_salt('bf', 10)) WHERE is_admin = true;"
# pgcrypto 扩展在 init_db.sql 建表时已启用，可直接使用 crypt()
```

日志入口速查：

```bash
docker compose logs -f --tail 200 backend    # 业务报错
docker compose logs -f --tail 200 nginx      # 5xx/转发问题
docker compose exec db psql -U postgres fly   # 直查数据库
```

## 10. 安全基线

1. **管理员密码**：初始化时在 `.env` 设置强随机 `ADMIN_INITIAL_PASSWORD`；忘记时按下方
   "重置管理员密码" 处理。
2. **`.env` 权限**：`chmod 600 /opt/fly/.env`；`POSTGRES_PASSWORD` 与
   `FLY_SECRET_KEY` 使用随机强值。
3. **端口收敛**：对外仅 80/443（云安全组同步只放行 22/80/443）。8000/3000 已绑定
   127.0.0.1，如需远程调试必须经 SSH 隧道。
4. **SSH**：建议禁用密码登录（`PasswordAuthentication no`）。
5. **HTTPS（已启用）**：`deploy/nginx.conf` 已拆为两个 server：80 全部 301 跳转 HTTPS，
   443 承载全部业务（TLS 1.2/1.3 + HTTP/2）。证书由 acme.sh 自动签发与续签
   （`~/.acme.sh/`），写入 `deploy/certs/`（`fullchain.pem` + `privkey.pem`），
   compose 已挂载 `./deploy/certs:/etc/nginx/certs:ro,z`。
   手动换证书后 `docker compose exec nginx nginx -s reload` 热加载；首次启用因
   端口/挂载变更需 `docker compose up -d nginx` 重建容器，且**证书文件必须先就位**，
   否则 nginx 起不来连带 80 一起挂。
   证书续签全自动化（一次性配置与排障见 6.5）；域名注册于阿里云、解析托管在
   阿里云云解析，签发插件为 `dns_ali`。
6. **定期更新系统**：`sudo dnf update -y`（重启内核后 `reboot`）。
7. **附加根证书说明**：镜像内**不带**任何附加根证书，构建与运行只信任系统/标准 CA，
   干净服务器开箱即用。仅当部署机所在网络存在 TLS 拦截（公司网/代理工具，如 SteamTools）
   导致构建期访问 npmmirror/aliyun 或运行期访问 biquga.com 报证书错误时，才需要把拦截
   工具的根证书导入构建/运行环境（backend 用 `keytool -importcert` 导入 JVM 信任库，
   Node 构建期用 `NODE_EXTRA_CA_CERTS` 指向 PEM 文件），并在 `docker-compose.yml` 的
   frontend 服务补回 `additional_contexts`。

## 13. 附录 C：迁移到新服务器

面向"整站搬到另一台服务器"。目标机只需 Docker 20+ 与 Compose v2。
镜像名已在 `docker-compose.yml` 固定为 `fly-frontend:1.0.1` / `fly-backend:1.0.1`，
因此 `docker save`/`load` 到任意目录名的机器上，`up` 都能直接命中镜像，不会重新构建。

### 13.1 路径 A：离线迁移（目标机不能联网构建，推荐）

```bash
# —— 源机 ——
docker compose build                       # 确保镜像是最新代码
docker save fly-frontend:1.0.1 fly-backend:1.0.1 \
            postgres:16-alpine nginx:alpine -o fly-images.tar
gzip fly-images.tar                   # 4 镜像约 1.2GB，gzip 后约 600MB

# 传镜像 + 项目目录（rsync/scp/内网均可）
scp fly-images.tar.gz user@new-host:/opt/fly/
rsync -av --delete --exclude node_modules --exclude .next --exclude .git \
      ./ user@new-host:/opt/fly/

# —— 目标机 ——
gunzip -c fly-images.tar.gz | docker load
cd /opt/fly
cp -n .env.example .env && vi .env         # 必填 FLY_SECRET_KEY
docker compose up -d                       # 注意：不带 --build
docker compose ps                          # 4 容器 Up，db 应为 healthy
```

要点：

- **不要带 `--build`**；带了会因为源码可能不全/网络不通而失败，`up` 只在镜像缺失时才构建。
- **若 rsync 带上了源机的 `.env`**（`cp -n` 不会覆盖它）：删掉 `MUSIC_DIR_120`/`MUSIC_DIR_MP3`
  两行 Windows 路径（留空即用 Linux 相对默认值），并建议轮换 `POSTGRES_PASSWORD` 与
  `FLY_SECRET_KEY`（旧值是源机测试值，勿带上线）。
- `deploy/nginx.conf`、`fly-backend/init_db.sql`、`fly-backend/init_admin.sh`、`fly-backend/uploads/` 必须随目录一起传：
  分别是 nginx 挂载、数据库首次建表脚本、管理员账号初始化脚本（挂载为 `zz-init-admin.sh`）、上传文件持久化目录。
- rsync 排除 `node_modules`/`.next` 只是加速传输；若希望目标机也能改代码重建，
  保留 `fly/`、`fly-backend/` 源码即可（`up --build` 需要它们）。

### 13.2 路径 B：在线迁移（目标机能联网构建）

```bash
rsync -av --delete --exclude node_modules --exclude .next --exclude .git \
      ./ user@new-host:/opt/fly/
ssh user@new-host 'cd /opt/fly && cp -n .env.example .env && vi .env \
      && docker compose up -d --build'
```

构建期依赖已内置国内源（npm → `registry.npmmirror.com`、Maven → 阿里云），
Docker Hub 基础镜像拉取仍需按 3.2 配置镜像加速。

### 13.3 数据迁移（二选一）

**A. 空库新装（最省事）**：直接 `up -d`，首次启动自动执行 `init_db.sql` 建表 + 站点配置种子
（pgcrypto 扩展），再由 `init_admin.sh`（`zz-init-admin.sh`）创建 `feifei` 管理员账号，站点配置为空库默认值。

**B. 带现有数据**：

```bash
# 源机导出
docker compose exec -T db pg_dump -U postgres fly | gzip > fly.sql.gz
tar -czf uploads.tar.gz fly-backend/uploads

# 目标机：先 up -d 让 db 起来，再清掉 init_db.sql 建的空表和种子，导入旧数据
docker compose up -d db
docker compose exec -T db psql -U postgres -d fly \
  -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
gunzip -c fly.sql.gz | docker compose exec -T db psql -U postgres fly
tar -xzf uploads.tar.gz -C /opt/fly
docker compose up -d
```

- 不清 schema 直接导入会与初始化脚本创建的数据冲突（`init_admin.sh` 创建的 `feifei` 账号重复；
  `ON CONFLICT DO NOTHING` 会跳过报错，但旧数据才是权威来源）。
- 音乐目录 `./data/music/` 非空时需一并 rsync；目录不存在时 Docker 会自动创建空目录，
  音乐功能为空但不影响启动，也可在 `.env` 里用 `MUSIC_DIR_120`/`MUSIC_DIR_MP3` 指向目标机已有路径。
